Session 3 cheat sheet

Helm → operators and CRDs → kube-prometheus-stack → PromQL and alerts → Loki, Alloy, LogQL. Names follow the lessons: release kps in namespace monitoring, app hello.

Helm: find and read a chart

  • helm repo add podinfo https://stefanprodan.github.io/podinfo register a chart repository
  • helm repo update refresh every repo's chart list
  • helm search repo podinfo charts and versions in added repos
  • helm show values podinfo/podinfo --version 6.17.0 every knob, with defaults
  • helm template demo podinfo/podinfo --version 6.17.0 -f values-podinfo.yaml render to plain YAML, send nothing

Chart = templates. Values = your parameters. Release = one installed copy. Rendering happens client side; the cluster only sees plain YAML.

Helm: install, change, undo

  • helm upgrade --install demo podinfo/podinfo --version 6.17.0 -f values-podinfo.yaml --dry-run=client preview (bare --dry-run is deprecated in Helm 4)
  • helm upgrade --install demo podinfo/podinfo --version 6.17.0 -f values-podinfo.yaml --wait install or upgrade, wait for ready
  • helm list · helm -n monitoring list releases, revision, chart version
  • helm history demo one row per install, upgrade, rollback
  • helm rollback demo 1 --wait old values as a new revision
  • helm get values demo what you supplied
  • helm uninstall demo · helm -n monitoring uninstall kps loki alloy
  • kubectl get secret -l owner=helm history: sh.helm.release.v1.demo.v3

Values file in git, never --set. Pin --version. Edit file → helm upgrade → check. Uninstall keeps CRDs: Helm never deletes them.

Operator pattern

CRD = a new kind in the API (kubectl get crd, kubectl explain servicemonitor.spec). CR = one object of that kind. Operator = a Pod that watches CRs and makes reality match: observe → diff → act → repeat. Level-triggered: it compares whole states, so missed events do not matter. Operator down: CRs are stored, nothing happens until it is back.

CR → what the operator makes

You applyOperator generates
PrometheusStatefulSet prometheus-kps-prometheus + its config Secret
AlertmanagerStatefulSet alertmanager-kps-alertmanager
ServiceMonitorscrape job serviceMonitor/<ns>/<name>/<i> in Secret prometheus-kps-prometheus; one target per Pod

config-reloader sidecar notices the new config and reloads Prometheus. Helm makes the CRs once; the operator works forever.

The release: kps gotcha

metadata:
  name: hello
  labels:
    release: kps    # or Prometheus ignores it
spec:
  selector:
    matchLabels:
      app: hello    # Service labels
  endpoints:
    - port: http    # Service port NAME
      path: /metrics
  • kubectl get prometheus -n monitoring kps-prometheus -o jsonpath='{.spec.serviceMonitorSelector}' → {"matchLabels":{"release":"kps"}}; ruleSelector the same

No label, wrong selector, or a port number instead of the port name: applied fine, no target, no error anywhere.

Config file vs operator

  • File: one shared prometheus.yml in a ConfigMap; kubelet syncs it (~1 min); you POST /-/reload; typo found only at reload, old config kept, restart crash-loops.
  • Operator: small CR per app, schema-checked on apply, auto reload, follows Pods, deleted CR = target gone. Cost: one more program running, one more layer to debug.
  • Loki, Alloy here: config-file way via Helm values → ConfigMap → sidecar reload (Alloy) or Pod replaced (Loki). No operator.

PromQL (RED)

# Rate: requests per second
rate(http_requests_total{job="hello"}[1m])
# by status code
sum by (status) (
  rate(http_requests_total{job="hello"}[1m]))
# Errors: share of 5xx
sum(rate(http_requests_total{job="hello",
  status=~"5.."}[1m]))
/ sum(rate(
  http_requests_total{job="hello"}[1m]))
# Duration: 95% are faster than
histogram_quantile(0.95, sum by (le) (rate(
  http_request_duration_seconds_bucket{
  job="hello"}[1m])))

Counters only go up: always rate(). [1m] for the lab, [5m] is usual in production. Labels: by route, never raw URL or IDs (cardinality).

Alerts

PrometheusRule with release: kps, expr + for: 2m. States: inactive → pending (true, waiting out for) → firing → Alertmanager. Watchdog always fires: that is the dead-man's switch.

Loki + Alloy

discovery.kubernetes
  # my node's Pods (HOSTNAME)
→ discovery.relabel
  # namespace, pod, container, app
→ loki.source.kubernetes
  # tail logs via the API
→ loki.write
  # push to loki.monitoring:3100

Alloy: DaemonSet, one per node. Loki: StatefulSet, SingleBinary + filesystem (chart default SimpleScalable needs object storage). Indexes labels only. Grafana data source: grafana.additionalDataSources in values-kps.yaml, then helm upgrade kps.

LogQL

# stream selector: labels, uses the index
{namespace="default", app="hello"}
# line filter: grep the text
{app="hello"} |= "boom"
# parser, then filter on a field
{app="hello"} | json | level="ERROR"
# logs → numbers
sum by (status) (count_over_time(
  {app="hello"} | json [5m]))

Selector is mandatory. Line filters early. IDs stay in the line (|= "id"), never a label. Promtail: EOL 2 March 2026; alloy convert --source-format=promtail.

Symptom → where to look

  • Target missing in Status → Target health → ServiceMonitor has release: kps? its selector matches the Service labels? port: is the Service port name? Then grep the generated config for serviceMonitor/<ns>/<name>
  • Target down → curl the /metrics path through a port-forward; the error text on the target row
  • Nothing reconciles → kubectl -n monitoring get deploy kps-operator (0/0?), kubectl -n monitoring logs deploy/kps-operator --tail=20
  • Alert never fires → rule has release: kps? Prometheus UI → Alerts lists it? run its expr alone in the query box; still pending: wait out for
  • Plain Prometheus ignores edit → file synced yet (~1 min, kubectl exec … cat)? reload sent? reload error = typo, old config still running
  • No logs in Loki → kubectl -n monitoring logs ds/alloy -c alloy --tail=20; Loki /ready; which labels exist (Label browser): no app label on that Pod?
  • Loki data source fails → URL http://loki.monitoring:3100; kubectl -n monitoring get pods,svc -l app.kubernetes.io/name=loki
  • Grafana login fails → read the password from Secret kps-grafana, user admin
  • helm upgrade did nothing → helm get values: is your change there? right -f file? helm history got a new revision?
  • Pods Pending / OOMKilled after install → Docker VM memory (≥ 6 GB); kubectl describe pod Events
