From Code to Cluster · Session 1 · reference

Session 1 cheat sheet

Docker → Dockerfile → kind → kubectl → Deployment + Service → probes and resources. Names follow the lessons: image hello, folder k8s/.

Docker: images

  • docker build -t hello:multi . build ./Dockerfile, name it name:tag
  • docker build -f Dockerfile.single -t hello:single . another Dockerfile
  • docker images hello list images and sizes
  • docker tag hello:multi hello:0.1.0 second name, same image
  • docker history hello:single layers, newest on top

Tags: version them (0.1.0, 0.1.1). Never :latest with kind: its pull policy is Always, so the loaded copy is ignored.

Docker: containers

  • docker run -d --name hello -p 8080:8080 hello:multi -d background, -p host:container
  • docker run -d --name hello -e PORT=9090 -p 8080:9090 hello:single -e env var
  • docker run -d --name hello -P hello:multi + docker port hello EXPOSEd port on a random host port
  • docker run --rm alpine ps remove container when it exits
  • docker run … -v hello-data:/data hello:multi named volume, outlives the container
  • docker ps · docker ps -a running · all, incl. exited
  • docker logs hello what the process printed
  • docker exec -it hello sh shell inside (none in distroless)
  • docker stop hello · docker rm hello · docker rm -f hello stop · remove · both
  • docker volume rm hello-data delete a named volume

Exit code 137 = killed. Docker does not restart it.

Dockerfile (multi-stage)

# stage 1: has the Go toolchain
FROM golang:1.27 AS build
WORKDIR /src          # cd for next steps
COPY go.mod ./        # rarely changes
COPY *.go ./          # changes often
RUN CGO_ENABLED=0 go build -o /server .

# stage 2: only what you copy across
FROM gcr.io/distroless/static-debian13:nonroot
COPY --from=build /server /server
EXPOSE 8080           # docs only, not -p
USER 65532:65532      # numeric = checkable
ENTRYPOINT ["/server"] # what starts
  • RUN runs at build time; CMD ["/server"] (lesson 03) also names what to start
  • Cache: first changed step and every step after it rebuild. Rarely changing steps go first.
  • .dockerignore keeps .git, *.md, Dockerfile* out of the build context

kind

  • kind create cluster one node, context kind-kind
  • kind delete cluster · --name fault-hunt also removes its context
  • kind load docker-image hello:0.1.0 copy image into the node
  • kind export kubeconfig write the context back
  • docker exec kind-control-plane crictl images images the node has (crictl ps: containers)

kubeconfig and context

~/.kube/config: clusters + users + contexts (cluster + user). Holds an admin key: never commit it.

  • kubectl config get-contexts * = current
  • kubectl config use-context kind-kind switch cluster
  • kubectl config view --minify only the current context
  • kubectl cluster-info · kubectl get nodes who am I talking to

kubectl: look

  • kubectl get pods -A all namespaces, -n kube-system
  • kubectl get pods -o wide + node and IP
  • kubectl get pods -w keep watching (Ctrl+C)
  • kubectl get pods -l app=hello --show-labels filter, show labels
  • kubectl get deploy,rs,pod · kubectl get svc -o wide
  • kubectl get pod hello -o yaml full object: spec + status
  • kubectl describe pod NAME State, Last State, Events: read bottom-up
  • kubectl logs POD · --previous program output · the run that died
  • kubectl events --for pod/NAME one object's story
  • kubectl get events --sort-by=.lastTimestamp all, newest last
  • kubectl get pods --sort-by=.metadata.creationTimestamp newest Pod last
  • kubectl get endpointslices -l kubernetes.io/service-name=hello Pods behind the Service
  • kubectl exec two -c sidecar -- wget -qO- hello call from inside a Pod

Order: get (which object?) → describe (why?) → logs (only if it started) → compare YAML with -o yaml / diff. Change one thing, apply, repeat.

kubectl: change

  • kubectl apply -f k8s/ make cluster match files; rerun is safe
  • kubectl diff -f k8s/ preview / spot drift
  • kubectl delete pod NAME · kubectl delete -f FILE
  • kubectl create deployment hello --image=hello:0.1.0 --dry-run=client -o yaml print a skeleton, send nothing
  • kubectl run crashy --image=hello:0.1.0 --env=PORT=notaport one bare test Pod
  • kubectl scale deployment hello --replicas=3 drift: next apply undoes it
  • kubectl set image deployment/hello hello=hello:0.1.2 container=image
  • kubectl rollout status deployment/hello --timeout=30s
  • kubectl rollout history deployment/hello
  • kubectl rollout undo deployment/hello emergency brake; fix the file after
  • kubectl port-forward service/hello 8080:80 then curl localhost:8080/
  • kubectl label pod NAME app=debug --overwrite take a Pod out of selectors

Commands forget, files remember: lasting changes go in k8s/*.yaml and git.

Deployment + Service

apiVersion: apps/v1
kind: Deployment
metadata:
  name: hello
  labels:
    app: hello
spec:
  replicas: 3
  selector:
    matchLabels:
      app: hello       # Pods it counts
  template:
    metadata:
      labels:
        app: hello     # = selector
    spec:
      containers:
        - name: hello
          image: hello:0.1.1
          ports:
            - containerPort: 8080 # docs
          resources:
            requests:
              cpu: 50m
              memory: 16Mi
            limits:
              memory: 62Mi
          startupProbe:    # others wait
            httpGet:
              path: /healthz
              port: 8080
            periodSeconds: 1
            failureThreshold: 10
          readinessProbe:  # no: no traffic
            httpGet:
              path: /healthz
              port: 8080
            periodSeconds: 5
          livenessProbe:   # no: restart
            httpGet:
              path: /healthz
              port: 8080
            periodSeconds: 10
---
apiVersion: v1
kind: Service
metadata:
  name: hello
spec:
  selector:
    app: hello         # Pods with this label
  ports:
    - port: 80         # Service listens
      targetPort: 8080 # container listens

Every object: apiVersion, kind, metadata, spec; cluster adds status. Selector ≠ template labels: rejected. Service selector matching nothing: accepted, no endpoints. DNS name: hello (hello.default.svc.cluster.local).

Probes

HTTP 200–399 = yes. Defaults: periodSeconds 10, timeoutSeconds 1, failureThreshold 3. Liveness asks about this process only, never a dependency. Delete: SIGTERM, wait terminationGracePeriodSeconds (30), then SIGKILL.

Resources, units, QoS

  • requests scheduler reserves it before the Pod runs; no room → Pending
  • limits kernel (cgroups) enforces: memory over → OOM kill; CPU over → slowed
  • request ≤ limit, else the API refuses it
  • 50m CPU millicores (1/20 core); 1 = one core
  • 16Mi · 1Gi memory, 1024-based. M = million; m on memory: never
  • QoS, evicted first → last: BestEffort (none set) → Burstable (some) → Guaranteed (CPU + memory requests = limits, every container)

Symptom → where to look

  • Pending → describe pod: FailedScheduling from default-scheduler: no node has room for the requests
  • ContainerCreating, forever → describe pod Events (e.g. FailedMount); check resources if the message makes no sense
  • ErrImagePull, ImagePullBackOff → describe pod, first Failed line above the bottom: image not on the node? crictl images, tag, kind load. logs is empty
  • CrashLoopBackOff, Error, RESTARTS rising → logs POD --previous: the dead run's last words; describe: Last State, Exit Code; events --for pod/NAME: "failed liveness / startup probe"?
  • OOM → describe: StartError "OOM-killed" (RunContainerError, logs empty) or Last State OOMKilled, Exit Code 137: memory limit
  • Running 0/1 → readiness failing: events --for pod/NAME "Readiness probe failed"; not ready in the EndpointSlice; rollout waits
  • Rollout stuck → rollout status, get rs, get deploy (UP-TO-DATE < replicas); read the newest Pod
  • Service, no endpoints → get endpointslices -l kubernetes.io/service-name=… empty: compare Service selector with get pods --show-labels
  • Connection refused → nothing listens at that IP and port. Via a Service: check its endpoints first. In probe Events: which port did the probe ask?
  • kubectl: "localhost:8080 was refused" → no current context: config get-contexts, kind export kubeconfig

Events bottom-up: last line = now; walk up to the first Warning with a real message. (x4 over 2m) = still retrying.
