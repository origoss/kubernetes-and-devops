Pre-flight check

Your win: the pre-flight script ends with a green ✔ PRE-FLIGHT PASSED, and your instructor has the screenshot.

Before this: a laptop you can install software on, your home network, and about 15 GB of free disk. This lesson is mandatory. Do it at least a few days before Session 1, so there is time to fix problems.

How this course works

The course is four in-person sessions, about a fortnight apart. Each one adds a layer to the same small project, a web server you write yourself:

SessionTopicWhat your project gains
1Containers and Kubernetesyour server, in a container, running on a local cluster
2CI/CDa pipeline that tests, builds and publishes it on every change
3Monitoring and loggingmetrics, dashboards, alerts and searchable logs
4GitOpsthe cluster deploys itself from your repository

The course materials live in one public repository: github.com/origoss/kubernetes-and-devops. It holds every lesson, homework brief and script. You clone it in step 3 below, and run git pull in it before each session to get the latest version.

Your work lives in your own Git repository. Everyone creates one public GitHub repository at the start (lesson 02 shows how) and keeps building in it until the end. After each session there is an exercise. You upload your solution to that repository as a pull request, add your instructor jagyugyaerik as a collaborator, and request their review. The instructor reviews every pull request between sessions, so feedback arrives before the next meeting.

Everything you need is in these lessons. Each lesson is short and gives you three things: the background, the exact commands with the output you should expect, and a quiz to check yourself. The exercises only need what the lessons cover. If you get stuck, reread the lesson first, then ask your instructor. There is no course chat channel yet; if you would like one, suggest it.

Using AI tools

Use as much AI as you like: to explain an error, to suggest a command, to review your code. One rule: never let an AI put anything into your work, or do anything on your machine, that you do not understand. Before you accept a line of code, a YAML field or a command, you can say what it does and why it is there. In the review, and in the room, you may be asked to explain any line of your pull request. "The AI wrote it" is not an answer.

Lessons marked before the session prepare you for the room. Lessons marked after the session repeat what we did there, step by step, so you can finish the exercise alone at home.

Why at home, and why now

In a full room, every laptop shares one wifi and one public IP address. Docker Hub lets anonymous users pull only 100 images per 6 hours per IP address.[1] The whole room would burn through that before lunch. So you do two things at home: you log in to Docker Hub, which gives you your own allowance of 200 pulls, and you download every image Session 1 needs in advance. That is about 3 GB, which is fine on your home network and painful on a shared one.

What your laptop needs

  • RAM: 16 GB recommended, 8 GB as the bare minimum. With 8 GB, close your browser tabs during the labs.
  • Virtualization switched on. Macs always have it. On Windows and Linux PCs it is a firmware (BIOS/UEFI) setting called VT-x, AMD-V or SVM.
  • Disk: about 15 GB free for images and clusters.

Containers need a Linux kernel (you will see why in lesson 01). On a Mac, Docker therefore runs inside a small Linux VM, and every container and every Kubernetes node you start lives inside that VM's memory, not your laptop's. kind's own docs ask for at least 6 GB for that VM and recommend 8 GB.[2] Docker Desktop gives its VM half of your Mac's memory by default. That is enough on a 16 GB Mac and too little on an 8 GB one, so you check it.

Do it

  1. Install a container engine. Pick your operating system.

    macOS: Docker Desktop

    Install Docker Desktop for Mac. Pick the Apple silicon or Intel download to match your Mac. It is free for personal use and education.[3] Start it once, then open Settings and check two things:[4]

    • Resources → Advanced → Memory limit: at least 6 GB, ideally 8 GB. The default is half of your Mac's memory, so an 8 GB Mac needs this raised as far as it will go.
    • Kubernetes: leave Enable Kubernetes unticked (it is off by default). We run our own clusters with kind, and a second cluster would only eat memory and CPU.

    Linux: Docker Engine

    Install Docker Engine (docker-ce) natively by following Docker's page for your distribution. Then let your user run docker without sudo, and log out and back in:[5]

    sudo usermod -aG docker $USER

    No VM on Linux: containers use your laptop's memory directly.

    Windows: WSL2 + Ubuntu, then Docker Desktop or Docker Engine

    In an administrator PowerShell, install WSL2 with Ubuntu, then reboot:[7]

    wsl --install -d Ubuntu

    Open the Ubuntu terminal. From now on, everything in this course happens inside that terminal, whichever engine you pick. Then choose one of the two:

    • Docker Desktop (easier). Install Docker Desktop for Windows with the WSL 2 backend. In Settings → Resources → WSL integration, switch it on for Ubuntu, and leave Kubernetes unticked, as on the Mac.[8] The docker command in your Ubuntu terminal then talks to Docker Desktop.
    • Docker Engine inside WSL (no Docker Desktop). Install Docker Engine in the Ubuntu terminal by following Docker's Ubuntu page, then run the usermod line from the Linux section.

    Either way, containers run in the WSL2 VM, which gets half of your PC's memory by default. With 8 GB of RAM, close other programs during the labs.[9]

    Do not use Rancher Desktop on Windows: kind create cluster fails on Rancher Desktop with WSL2, and the bug is still open (rancher-desktop #5604).

    On every OS, check that the engine works:

    docker run --rm hello-world

  2. Install kind v0.33.0, kubectl, Go 1.27 and git.

    macOS, with Homebrew:

    brew install kind kubectl go git

    Linux and WSL (Ubuntu/Debian; the same URLs work on other distributions):

    ARCH=$(dpkg --print-architecture)
curl -Lo kind https://kind.sigs.k8s.io/dl/v0.33.0/kind-linux-$ARCH
sudo install -m 0755 kind /usr/local/bin/kind && rm kind
curl -LO https://dl.k8s.io/release/v1.37.1/bin/linux/$ARCH/kubectl
sudo install -m 0755 kubectl /usr/local/bin/kubectl && rm kubectl
curl -LO https://go.dev/dl/go1.27.1.linux-$ARCH.tar.gz
sudo rm -rf /usr/local/go && sudo tar -C /usr/local -xzf go1.27.1.linux-$ARCH.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.bashrc && source ~/.bashrc
sudo apt-get install -y git

    Check the versions:

    kind version; kubectl version --client; go version; git --version
    Expected output (Linux arm64 shown)

Kustomize Version: v5.8.1

git version 2.43.0

    The go1.26.7 in kind's line is the Go version kind was built with, not yours. Also create a GitHub account if you do not have one; lesson 02 puts your code there.

  3. Clone the course materials. Pick a folder for the course and clone the repository there (on Windows, inside the Ubuntu terminal):

    git clone https://github.com/origoss/kubernetes-and-devops.git
    cd kubernetes-and-devops

    You can open the lessons from lessons/ in your browser, offline. Before each session, update them:

    git pull

  4. Log in to Docker Hub. Create a free account at hub.docker.com, then:

    docker login

    Follow the prompt. It may show a one-time code and open your browser. You stay logged in, so you do this once.[6]

    docker pull golang:1.27

docker pull python:3.12-slim
docker pull python:3.13-slim

    Expected output (end of each pull) 
    Status: Downloaded newer image for golang:1.27
docker.io/library/golang:1.27

    If a pull says Image is up to date, you already had it. Fine too.

If something fails

  • permission denied ... docker.sock (Linux/WSL): you skipped the usermod line, or did not log out and back in.
  • Cannot connect to the Docker daemon: start Docker Desktop. On Linux and with Docker Engine inside WSL: sudo systemctl start docker.
  • The command 'docker' could not be found in this WSL 2 distro (Windows with Docker Desktop): switch on WSL integration for Ubuntu in Docker Desktop's settings.
  • toomanyrequests on a pull: you hit the Docker Hub limit. Run docker login and try again later.
  • kind fails or hangs: check the memory setting first, then kind's known issues.
