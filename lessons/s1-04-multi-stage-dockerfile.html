Session 1 · Docker · about 15 minutes

Ship your server in a 20 MB box

Your win: a container image of your own web server that is about 70× smaller than the naive one and runs as a non-root user.

Before this: you have a Go server with / and /healthz that reads its port from PORT, and Docker running (with Rancher Desktop, use the dockerd engine).

The idea

An image is a stack of read-only layers: each instruction in a Dockerfile adds one.[1] Everything a layer adds stays in the image for good, including the whole Go toolchain you only needed for one minute to compile.

A multi-stage build fixes this. The first stage has the compiler and builds the binary. The second stage starts from an almost empty base and copies only the binary across with COPY --from. Nothing else from the first stage reaches the final image.[2]

Go makes this dramatic: with CGO_ENABLED=0 the binary is static, so the run stage needs no OS libraries at all. Google's distroless static image is about 2 MB and ships a ready-made nonroot user.[3]

Why bother? Smaller images pull faster onto every cluster node. An image with no shell and no package manager also leaves an attacker nothing to work with, and running as non-root limits what a compromised process can do.[4]

Do it

  1. Build the naive image first, so you have something to compare against. Save this next to main.go:

    Dockerfile.single

    FROM golang:1.27
WORKDIR /src
COPY . .
RUN go build -o /server .
CMD ["/server"]
    docker build -f Dockerfile.single -t hello:single .

  2. Now the real one. Read every line before you save it, and use the comments to check that you know why each line is there.

    Dockerfile

    # Stage 1: build: has the Go toolchain
FROM golang:1.27 AS build
WORKDIR /src
# go.mod changes rarely → this layer stays cached
COPY go.mod ./
# your code changes often → only this step and below rebuild
COPY *.go ./
RUN CGO_ENABLED=0 go build -o /server .

# Stage 2: run: only your binary
FROM gcr.io/distroless/static-debian13:nonroot
COPY --from=build /server /server
USER nonroot
EXPOSE 8080
ENTRYPOINT ["/server"]

    Add a .dockerignore so the build context stays small:[5]

    .git
*.md
Dockerfile*
    docker build -t hello:multi .

  3. Compare the two images.

    docker images hello
    Expected output (sizes vary by Docker version) 
    REPOSITORY   TAG      ...   SIZE
hello        multi    ...   19.1MB
hello        single   ...   1.43GB

  4. Run it, publishing container port 8080 on your laptop's port 8080, and ask it something.

    docker run -d --name hello -p 8080:8080 hello:multi
    curl localhost:8080/healthz
    docker logs hello
    Expected output 
    ok
2026/10/05 22:12:13 listening on :8080

  5. Prove it is not root, then try to look around inside.

    docker inspect hello:multi --format '{{.Config.User}}'
    docker exec -it hello sh
    Expected output 
    nonroot
OCI runtime exec failed: exec failed: unable to start container process:
exec: "sh": executable file not found in $PATH: unknown

    That error is the point: there is no shell to exec into. When you need to debug a distroless container, you attach a debug container instead; you will meet kubectl debug later.

  6. Clean up.

    docker rm -f hello
