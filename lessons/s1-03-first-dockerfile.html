Your first Dockerfile

Your win: your own server runs in a container you built from your own Dockerfile, and you can look inside it, read its logs and see its layers.

Before this: your hello repo from lesson 02 (go.mod and main.go), and Docker running (the pre-flight check passed).

A recipe for an image

A Dockerfile is a recipe: a list of instructions that turn a folder of files into an image.[1] You will use five of them:

  • FROM: the image you start from. Here golang:1.27, which has Go installed.
  • WORKDIR: the folder the next instructions work in.
  • COPY: copy files from your folder (the build context) into the image.
  • RUN: run a command at build time, here the compiler.
  • CMD: what to start when a container runs from the image.

Each instruction adds a read-only layer on top of the previous one.[2] Layers make rebuilds fast. If an instruction and its input files have not changed, Docker reuses the old layer (CACHED). The first changed step, and every step after it, is rebuilt.

Do it

  1. In your hello folder, next to main.go, save this file. It is deliberately naive: one stage, the whole Go toolchain included. Lesson 04 improves it.

    Dockerfile.single

    FROM golang:1.27
WORKDIR /src
COPY . .
RUN go build -o /server .
CMD ["/server"]

  2. Build an image from it and name it hello:single. -f picks the file, -t sets the name and tag, and the final . is the build context: the folder Docker may copy from.

    docker build -f Dockerfile.single -t hello:single .
    Expected output (trimmed) 
    [+] Building 8.3s (9/9) FINISHED
 => [internal] load build definition from Dockerfile.single
 => [1/4] FROM docker.io/library/golang:1.27@sha256:e0174e51e812...
 => [internal] load build context
 => [2/4] WORKDIR /src
 => [3/4] COPY . .
 => [4/4] RUN go build -o /server .
 => exporting to image
 => => naming to docker.io/library/hello:single

  3. Run a container from it in the background (-d), name it hello, and publish its port 8080 on your laptop's port 8080 (-p laptop:container).[3]

    docker run -d --name hello -p 8080:8080 hello:single
    docker ps
    curl localhost:8080/healthz
    Expected output 
    2182b545124e86c8b5e0d68c0d75aeb7f737f9228c738dc5e1e49cfd58c9e0ce
CONTAINER ID   IMAGE          COMMAND     CREATED        STATUS        PORTS                                         NAMES
2182b545124e   hello:single   "/server"   1 second ago   Up 1 second   0.0.0.0:8080->8080/tcp, [::]:8080->8080/tcp   hello
ok

  4. Read its logs. Everything your server writes to the terminal is kept by Docker.

    docker logs hello
    Expected output 
    2026/10/05 22:28:18 listening on :8080

  5. Open a shell inside the running container and look around. This works because the golang image is a full Debian system with a shell. Remember that for lesson 04.

    docker exec -it hello sh
    # whoami
root
# ls
Dockerfile.single  go.mod  main.go
# exit

    Two surprises. The container runs as root. And COPY . . copied everything in your folder, the Dockerfile too.

  6. Stop and remove the container. A stopped container still exists and still holds its name, until you remove it.

    docker stop hello
    docker rm hello

  7. Configure it from outside, as in lesson 02: tell the server to listen on 9090 inside the container, and publish that on your laptop's 8080.

    docker run -d --name hello -e PORT=9090 -p 8080:9090 hello:single
    curl localhost:8080/healthz
    docker logs hello
    Expected output 
    ok
2026/10/05 22:28:27 listening on :9090
    docker rm -f hello

    rm -f stops and removes in one go.

  8. See the layers your Dockerfile made:

    docker history hello:single
    Expected output (trimmed) 
    IMAGE          CREATED          CREATED BY                                      SIZE
9331de85b3ce   24 seconds ago   CMD ["/server"]                                 0B
<missing>      24 seconds ago   RUN /bin/sh -c go build -o /server . # build…   100MB
<missing>      29 seconds ago   COPY . . # buildkit                             20.5kB
<missing>      29 seconds ago   WORKDIR /src                                    8.19kB
<missing>      2 weeks ago      WORKDIR /go                                     4.1kB
...
<missing>      2 weeks ago      COPY /target/ / # buildkit                      290MB
...
<missing>      2 weeks ago      RUN /bin/sh -c set -eux;  apt-get update;  a…   280MB
<missing>      2 weeks ago      RUN /bin/sh -c set -eux;  apt-get update;  a…   208MB
<missing>      2 weeks ago      RUN /bin/sh -c set -eux;  apt-get update;  a…   63.7MB
<missing>      2 weeks ago      # debian.sh --arch 'arm64' out/ 'trixie' '@1…   156MB

    Read it bottom-up. Your four lines sit on top; everything below came with golang:1.27: Debian, build tools, the Go toolchain. Your RUN layer is 100 MB, although the server binary is only 8 MB. The rest is Go's build cache, which stays in the image for good.

  9. Watch the cache work. Add a comment line at the end of main.go (for example // a small change), then build again:

    docker build -f Dockerfile.single -t hello:single .
    Expected output (trimmed) 
    [+] Building 7.7s (9/9) FINISHED
 => [1/4] FROM docker.io/library/golang:1.27@sha256:e0174e51e812...
 => [internal] load build context
 => CACHED [2/4] WORKDIR /src
 => [3/4] COPY . .
 => [4/4] RUN go build -o /server .
 => exporting to image

    WORKDIR came from cache. COPY . . saw a changed file, so it and everything after it ran again. Build once more without changing anything, and all three steps say CACHED; the build takes under a second.

  10. Finally, look at the size:

    docker images hello
    Expected output 
    REPOSITORY   TAG       IMAGE ID       CREATED         SIZE
hello        single    bf5871c35369   3 seconds ago   1.43GB

    1.43 GB to ship an 8 MB program. Every cluster node that runs it must download all of that. Lesson 04 gets it under 20 MB. Keep hello:single: lesson 04 compares against it.
